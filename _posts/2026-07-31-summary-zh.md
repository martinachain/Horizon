## [安全专家警告：警惕预装恶意软件的电视流媒体棒](https://krebsonsecurity.com/2026/07/read-this-before-you-buy-that-tv-streaming-stick/) ⭐️ 8.0/10

KrebsOnSecurity 于 2026 年 7 月发布详细报告，警告称廉价电视流媒体棒（如 H96 型号）预装了用于广告欺诈和住宅代理滥用的恶意软件。文章指出，这些设备可以静默启动浏览器、访问网站、点击广告，并在电视关闭时出租用户的互联网连接。 这一警告意义重大，因为这些设备在主流电商平台上广泛销售，许多消费者在不知情的情况下将家庭网络暴露于犯罪活动之中。报告强调了在物联网安全方面，供应商需要承担更大责任，消费者也需要提高警惕。 这些设备上的恶意软件使用 Blockly 模块执行欺诈任务，如静默启动浏览器、访问网站、管理标签页和点击广告。当电视开启时，设备通常作为住宅代理运行；当电视关闭时，则切换至广告欺诈任务。FBI 和安全行业已多次警告这些风险，但这些设备仍在亚马逊、百思买和新蛋等平台有售。

hackernews · speckx · Jul 30, 17:04 · [社区讨论](https://news.ycombinator.com/item?id=49112744)

**背景**: 住宅代理通过真实设备路由互联网流量，隐藏 IP 地址，常被用于广告欺诈、网络爬虫和产品抢购。攻击者通过入侵流媒体棒等物联网设备来构建代理网络，这些设备因其常开状态和缺乏安全更新而具有吸引力。报告指出，即使没有预装恶意软件，维护不善、运行旧版 Android 的设备也容易被劫持用于此类滥用。

## [GitHub 推出堆叠式拉取请求公开预览](https://github.blog/changelog/2026-07-30-stacked-pull-requests-are-now-in-public-preview/) ⭐️ 8.0/10

GitHub 宣布堆叠式拉取请求（Stacked PRs）功能现已进入公开预览，该功能用于管理相互依赖的拉取请求。开发者可以将拉取请求按顺序排列成堆栈，并一次性合并所有请求。 该功能意义重大，因为它将一种强大的工作流程引入全球最大的代码托管平台之一，有望提高代码审查效率和开发者的生产力。同时，它也可能让许多开发者接触到以前不熟悉的堆叠式 PR 工作流程。 公开预览版包含 UI 和 CLI 支持，GitHub 表示这是其历史上规模最大的发布之一，涉及 Actions 等服务。然而，一些用户报告了 bug，例如在某些情况下合并整个堆栈会失败，以及使用 squash 合并时每个 PR 都需要重新审批。

hackernews · tomzorz · Jul 30, 16:26 · [社区讨论](https://news.ycombinator.com/item?id=49112232)

**背景**: 堆叠式拉取请求（或堆叠式差异）是一种工作流程，将一系列小而相互依赖的变更堆叠在一起，每个变更位于自己的分支和拉取请求中。这种方法允许独立审查每个变更，同时仍然一起合并，从而可能提高代码质量并加快审查周期。传统上，这种工作流程由 Graphite 等第三方工具支持，而 GitHub 的原生支持将其带给更广泛的用户。
