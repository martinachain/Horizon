**背景**: 大型语言模型（LLM）传统上在训练时将知识存储在参数中，但最近的方法越来越多地集成外部工具，如搜索引擎或代码解释器。这减少了模型记忆事实的需求，但引发了关于基准有效性和离线性能的问题。知识与工具使用之间的权衡是一个活跃的研究领域，相关研究正在探索如何平衡两者。

## [发展中国家嵌入式工程师为 RISC-V 的可及性辩护](https://rvembedded.com/blog_post/12/) ⭐️ 7.0/10

一位来自发展中国家的嵌入式工程师发表了对《RISC-V 他们本应更了解》一文的回应，认为 RISC-V 的开放性和低成本使其在资源有限地区的嵌入式开发中具有独特的可及性。回应强调了在关于 RISC-V 性能和碎片化的讨论中常被忽视的成本和运输挑战的重要性。 这一观点通过引入发展中国家开发者的视角，拓宽了关于 RISC-V 的讨论，在这些地区成本和可及性至关重要。它挑战了性能和碎片化是唯一重要问题的假设，并表明 RISC-V 的 affordability 可能推动其在新兴市场的采用，从而可能塑造全球嵌入式系统的格局。 作者指出，由于他所在的位置，运送 1 美元的芯片可能需要 60 至 200 美元的运费，但后来声称 RISC-V 提供了“一种以每片十美分的价格到达我国的架构”，评论者指出了这一矛盾。原文批评 RISC-V 与 ARM64 相比性能不佳，以及由于 ISA 部分可选导致的碎片化，而回应则侧重于成本至关重要的嵌入式用例。

hackernews · Narishma · Aug 16, 17:01 · [社区讨论](https://news.ycombinator.com/item?id=49321717)

**背景**: RISC-V 是一种基于精简指令集计算（RISC）原理的免费开放指令集架构（ISA），与 x86 和 ARM 等专有 ISA 不同。它旨在供任何人免费使用、修改和实现，无需许可费用，使其在成本为主要关注点的嵌入式系统中具有吸引力。关于 RISC-V 的争论通常集中在其与成熟架构相比的性能，以及由于可选扩展而导致的碎片化可能性。

## [Buf 发布 Protobuf LSP，引发社区批评](https://buf.build/blog/protobuf-lsp) ⭐️ 6.0/10

Buf 宣布推出首个功能完备、生产级的 Protobuf 语言服务器协议（LSP）服务器，声称首次为 Protobuf 带来现代 IDE 支持。该公告发布在 Buf 博客上，并已集成到 Buf CLI 中。 这很重要，因为 Protobuf 广泛用于定义数据模式，改进的 IDE 支持可以提高开发者的生产力。然而，社区的反应表明该公告可能言过其实，因为现有的 LSP 和 IDE 插件已经提供了类似功能。 新的 LSP 已集成到 Buf CLI 中，Buf 已将其之前的原型语言服务器（bufls）归档，转而采用这一新实现。该帖子的语气，尤其是“You're welcome”这一短语，招致了批评，一些评论者指出，该实现从头重新实现了 Protobuf 解析器，而不是复用现有的解析器。
