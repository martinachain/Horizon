OpenAI released the Agents API, a hosted service that lets developers create production-ready agents in a single API call by specifying the task, model, tools, and environment, with OpenAI hosting and maintaining the underlying harness. The API is built around four concepts — Agent, Environment, Session, and Events/items — and includes automatic context compaction, multi-agent orchestration, programmatic tool calling, and MCP support. This marks OpenAI's push to own the agent infrastructure layer, not just the model, potentially simplifying agent deployment for developers who don't want to build and operate their own harness. It intensifies the debate over agent abstractions and vendor lock-in, as competitors like LangGraph, CrewAI, and Microsoft Agent Framework offer alternative orchestration approaches. The API runs the Codex harness and supports an optional self-hosted sandbox, which can ease transitions between providers and reduce lock-in concerns. However, some developers question whether a hosted service is necessary when hosting a Python service is already easy, and others note that the abstraction may not fit use cases where the main friction is provisioning access to local data.

**Background**: AI agents are systems that use large language models to autonomously perform multi-step tasks, calling tools and interacting with environments. Building an agent requires a 'harness' — the orchestration layer that manages state, tool calls, and context — which is complex to build and operate. OpenAI's Agents API offers this harness as a hosted service, similar to how cloud platforms abstract away servers, but raising questions about control, portability, and lock-in.
