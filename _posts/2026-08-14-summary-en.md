## [Single log line causes 49KB+ ext4 / 110KB+ btrfs disk writes in systemd-journald](https://github.com/systemd/systemd/issues/40262) ⭐️ 8.0/10

A GitHub issue reports that a single log line can trigger 49KB+ of disk writes on ext4 and 110KB+ on btrfs in systemd-journald, highlighting severe write amplification. The issue was filed against systemd version 257.9 on Debian 13 with kernel 6.12.57. This issue underscores a significant performance and storage inefficiency in systemd-journald, which is the default logging system on most modern Linux distributions. It can lead to excessive disk I/O, increased flash wear on SSDs, and reduced system performance, affecting a wide range of users and administrators. The write amplification is attributed to journald's design, which appends data and updates metadata, combined with filesystem journaling overhead. On btrfs, copy-on-write (CoW) behavior further amplifies writes, while ext4's traditional journaling also adds overhead. The issue suggests that log writes should be within an order of magnitude of the actual log size, but they are not.

hackernews · ValdikSS · Aug 13, 18:41 · [Discussion](https://news.ycombinator.com/item?id=49290215)

**Background**: systemd-journald is a system service that collects and stores logging data in a binary format, designed for reliability and fast access. It uses a journal file format inspired by classic log files and git repositories, appending data at the end for robustness. However, this design, combined with filesystem journaling (ext4) or copy-on-write (btrfs), can lead to significant write amplification, where the actual disk writes far exceed the logical log size. This issue has been a long-standing concern, with previous reports of excessive disk I/O and CPU usage.
