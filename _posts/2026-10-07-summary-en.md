## [OpenAI Shares AI-Generated Proofs of Major Math Conjectures](https://openai.com/index/sharing-ai-progress-in-mathematics/) ⭐️ 10.0/10

OpenAI published a GitHub repository (openai/math) containing mathematical manuscripts and Lean proof formalizations produced by an internal frontier model, including claimed proofs of the Unique Games Conjecture and Barnette's Conjecture. The release was accompanied by a companion page titled 'Sharing AI progress in mathematics' and covers 722 manuscripts addressing open research problems. If verified, these results would represent a paradigm shift in mathematical research, as the Unique Games Conjecture underpins many hardness-of-approximation results in theoretical computer science and Barnette's Conjecture has remained open for decades. The news has generated intense discussion (767 points, 695 comments), with researchers noting that textbooks may need rewriting and that AI is beginning to answer long-standing questions about the limits of human mathematical understanding. The repository includes preprints and Lean proof formalizations, with Barnette's Conjecture listed as problem 180; the proofs appear approachable at first glance according to commenters who previously attempted the problem with state-of-the-art models. The model used is described only as an 'internal OpenAI model' and has not been publicly named or released.

**Background**: The Unique Games Conjecture, proposed by Subhash Khot in 2002, posits that approximating the value of a certain type of game is NP-hard, and it has broad implications for the hardness of approximation of many optimization problems. Barnette's Conjecture, an open problem in graph theory, states that every bipartite polyhedral graph with three edges per vertex has a Hamiltonian cycle. Lean is an interactive theorem prover that allows mathematical proofs to be formalized and machine-verified, providing a way to check the correctness of AI-generated proofs.

"Trained from scratch" means Mistral built the model from the ground up rather than fine-tuning an existing one, and "open-weight" means the model weights are publicly available.

## [Google releases EmbeddingGemma 2, an open multimodal embedding model](https://blog.google/innovation-and-ai/technology/developers-tools/embeddinggemma-2/) ⭐️ 8.0/10

Google DeepMind launched EmbeddingGemma 2, an open-weight multimodal embedding model under the Apache 2.0 license that natively maps text, images, video frames, and audio into a single unified vector space. It is among the strongest multimodal embedding models under 1B parameters, with a text-only variant running in about 191MB of RAM on a Pixel 11 Pro. This gives developers an open, commercially usable option for multimodal retrieval that can run locally on devices, rather than relying on a cloud embedding API. It fills a gap for a good moderate-size open embedding model at a time when LLM and agent workflows increasingly depend on embeddings. The model totals 440M parameters for text plus vision, with 270M for text only, and unlike prior on-device embedding models it is trained with MRL rather than MatFormers, so you cannot shrink the model weights alongside lower-dimensional embeddings. For on-device deployment, developers can use Google AI Edge's MediaPipe and LiteRT, including a Semantic Retriever task that runs approximate nearest neighbour searches in single-digit milliseconds.

hackernews · ilreb · Oct 6, 16:03 · [Discussion](https://news.ycombinator.com/item?id=49980487)

**Background**: Embedding models convert text, images, and other content into numeric vectors so that similar items end up close together in vector space, which powers search, recommendation, and retrieval-augmented generation. Multimodal embeddings extend this to multiple content types in one shared space, and on-device AI means running such models locally on phones or edge hardware instead of sending data to the cloud. Apache 2.0 is a permissive open-source license that allows commercial use and modification.

An open-source project called AnyPS5 has been released on GitHub, aiming to run PlayStation 5 games natively on Windows and Linux without emulation by relinking PS5 executables into the host system's native format and reimplementing the console's system libraries for dynamic linking. Its GitHub page reports that 87% of the functions known to the project so far have been mapped, and a verified 2D platformer, Dreaming Sarah, runs at a stable 60 fps on a GTX 1050 Ti / i5-7500. This is a highly novel technical achievement with significant implications for reverse engineering, game preservation, and platform lock-in, potentially allowing PC players to run console exclusives such as GTA 6 shortly after release. It also intensifies the debate over legal risks, as similar projects like Yuzu and Ryujinx were previously taken down through legal threats, and could push console makers further toward cloud gaming to prevent such efforts. The 87% figure refers only to the percentage of functions known to the project so far (declared in core/libs/prx), not of every PS5 system function, and the total grows as more functions are declared. The project is described as a tool for automatic PS5 binary relinking and system library reimplementation, and its verified compatibility currently extends to at least one 2D platformer running at 60 fps on modest hardware.

AnyPS5 instead uses binary translation and relinking, converting PS5 executables into the host system's native format and reimplementing the console's system libraries for dynamic linking, which can be much faster than emulation. This approach is part of a broader trend of AI-assisted reverse engineering efforts that aim to democratize access to console games and reduce vendor lock-in.

## [OpenTPU: An Open-Source AI Accelerator Designed by AI Itself](https://github.com/FeSens/openTPU) ⭐️ 8.0/10

OpenTPU is an open-source AI inference accelerator that was developed using AI techniques and then improved through a recursive self-improvement loop, going from only a few tokens per second to over 80 tokens/sec on smaller models. It is an open reimplementation of Google's Tensor Processing Unit (TPU) built on FPGA, and it can run most modern models such as Qwen 3.5 and Gemma 4. This project demonstrates that AI can meaningfully participate in designing the hardware that runs AI models, potentially shortening accelerator design cycles and lowering the barrier to custom silicon. If the recursive self-improvement loop continues, it could reshape how AI chips are built and who can build them, affecting hardware startups, cloud providers, and the open-source hardware community. OpenTPU spans hardware, instruction set, compilation, simulation, and host control, making it a fully transparent FPGA-based accelerator that can be inspected or extended end-to-end. The recursive self-improvement loop is the key mechanism behind the performance jump, though the 80+ tokens/sec figure applies specifically to smaller models rather than frontier-scale ones.

hackernews · fsbonetto · Oct 6, 16:23 · [Discussion](https://news.ycombinator.com/item?id=49980715)

**Background**: A TPU (Tensor Processing Unit) is a specialized chip designed by Google to accelerate machine learning workloads more efficiently than general-purpose GPUs. An FPGA (Field-Programmable Gate Array) is a reconfigurable chip that can be reprogrammed after manufacturing, making it a flexible platform for prototyping custom accelerators. Recursive self-improvement (RSI) refers to AI systems rewriting and testing their own code to improve their capabilities, a concept often discussed in the context of AGI safety and intelligence explosions.
