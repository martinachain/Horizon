## [Android 17 QPR1 新增 Pixel 独占 API，未向 AOSP 发布](https://grapheneos.social/@GrapheneOS/117282080803799576) ⭐️ 8.0/10

GrapheneOS 指出，随 9 月 Pixel Drop 发布的 Android 17 QPR1 是自 Honeycomb（3.x）以来首个仅面向 Pixel 设备新增应用 API、却未同步发布到 Android 开源项目（AOSP）的版本。这些新 API 和平台改动目前仅存在于 Pixel 系统镜像中，其他 Android OEM 和第三方 ROM 项目均无法获取。 这标志着 Google 对 Android 开源开发治理方式的重大转变，可能导致平台碎片化，并削弱 GrapheneOS 等第三方 ROM 在功能和安全上紧跟 Pixel 设备的能力。这也引发了外界对 Google 对 AOSP 长期承诺以及开源 Android 生态可持续性的更广泛质疑。 根据社区分析，Google 目前每半年才向 OEM 和公众发布一次完整的 Android 源代码更新，而每年为 Pixel 发布四次包含文档和 SDK 的更新；此次新 API 正是出现在仅面向 Pixel 的更新中。GrapheneOS 多年来一直能获取每月的安全补丁回移，但这是首次新 API 被完全排除在 AOSP 之外。

hackernews · theanonymousone · Sep 18, 19:03 · [社区讨论](https://news.ycombinator.com/item?id=49758736)

**背景**: AOSP 是构建 Android 的开源代码库，GrapheneOS 等第三方 ROM 依赖它来打造注重隐私和安全的 Android 版本。历史上，Google 通常会在 Pixel 更新的同时或不久后将新 Android API 发布到 AOSP，使整个生态得以采用。Android 17 于 2026 年 6 月 16 日发布，QPR1 是其首个季度平台更新。GrapheneOS 是一个非营利开源移动操作系统，专注于隐私和安全，主要支持 Google Pixel 设备。

## [Cloudflare 借助数学与 Rust 节省 100TB 内存](https://blog.cloudflare.com/saving-100-tb-of-ram-with-math/) ⭐️ 8.0/10

Cloudflare 发布博客文章，详细介绍了其如何通过将统计学和数学技术应用于数十亿缓存条目的存储方式，在基于 Pingora 的 DNS 缓存服务中减少了 100TB 的内存占用。该优化同时提升了缓存速度，并在 Hacker News 上引发了关于内存优化和替代哈希策略的广泛讨论。 这表明，除了硬件扩展之外，通过算法和数学洞察仍能实现显著的基础设施成本和资源节约，这在内存成本上升、云服务商追求效率的背景下愈发重要。这些技术以及社区提出的替代方案可能会影响分布式系统处理大规模缓存和一致性哈希的方式。 该优化针对 Cloudflare 的 1.1.1.1 DNS 缓存，该缓存存储了数十亿条目，节省来自应用于内存布局的统计方法，而非简单增加硬件。一位评论者（vlovich123）提出用预计算的 SHA-256 哈希和 wyhash 的 wymum 替代一致性哈希和 Ketama，声称可额外节省 600TiB。

hackernews · f311a · Sep 18, 18:51 · [社区讨论](https://news.ycombinator.com/item?id=49758580)

**背景**: Cloudflare 运营着庞大的全球网络，其 1.1.1.1 公共 DNS 解析器依赖在内存中缓存数十亿条 DNS 记录以快速响应查询。Pingora 是 Cloudflare 基于 Rust 构建的网络服务框架，而一致性哈希（包括 Ketama 算法）是一种常见技术，用于在服务器之间分布数据，并在增删服务器时尽量减少数据重排。由于在云规模下内存依然昂贵，即使每个条目节省少量内存，也能累积成巨大的总量削减。

## [Cactus Needle 3 发布 8-29MB 自动化模型，性能对标 DeepSeek V4 Flash](https://cactuscompute.com/needle) ⭐️ 8.0/10

Cactus 发布了 Needle 3，这是一系列专注于工具调用和结构化 JSON 输出的模型，以 8-29MB 的 2-bit 二进制形式发布；在 Mobile Actions 基准上，20 层版本得分 86.0，高于 LFM2.5 1.2B 的 82.4 和 Qwen3.5 0.8B 的 76.0。此次更新引入了智能阶梯（2 到 20 层每一层都是可部署子网络）、Monarch Hadamard MLP、七种语言的多语言支持、基于正则表达式的触发器、校准置信度评分，以及对包括 WebAssembly 和 WASI 组件在内的广泛平台支持。 如果 8-29MB 的微型模型真的能在狭窄的自动化任务上媲美大得多的模型，那么设备端智能体就能在树莓派 5、手机、手表和浏览器等硬件上实用化，无需云端往返。这将把工具调用部署的经济性转向本地推理和针对特定任务的微调，而非依赖大型通用 LLM。 Needle 3 刻意不支持聊天；当没有匹配的已声明工具时，它会返回空列表，并使用 rank-8 输入条件门控以及 Walsh-Hadamard 初始化的 Kronecker（Monarch）因子对，将 FFN 成本从 O(d²) 降至 O(d√d)。Cactus 声称仅用 4 层微调即可在狭窄任务上达到 DeepSeek V4 Flash 级别的性能，在树莓派 5 上解码速度最高可达 4k tokens/秒，预填充最高可达 10k。

hackernews · HenryNdubuaku · Sep 18, 00:11 · [社区讨论](https://news.ycombinator.com/item?id=49748553)

**背景**: 小型语言模型以牺牲通用能力换取体积和速度，这使其在设备端自动化方面很有吸引力，但在开放式聊天上表现较弱。工具调用指模型输出结构化的函数调用（例如打开灯）而非自然语言，结构化 JSON 输出则指其输出机器可读的数据。Needle 3 正是针对这些狭窄格式，利用 Monarch 矩阵和 Walsh-Hadamard 变换等架构技巧来压缩通常占参数大头的的前馈网络。

## [光子发射引导激光故障注入攻破 RP2350 安全调试](https://donjon.ledger.com/blog/rp2350-secure-debug-laser-fault-injection/) ⭐️ 8.0/10

Ledger Donjon 的研究人员展示了一种光子发射引导的激光故障注入攻击，成功绕过了 RP2350 微控制器的安全调试保护。他们利用差分光子发射显微镜定位调试使能寄存器，然后用激光翻转两个比特位，在 RP2350 A4 芯片上恢复了安全调试访问权限。 这一攻击凸显了现代硬件攻击的复杂性，并表明此类技术可能用更低成本的设备复现，可能削弱依赖 RP2350 安全飞地的设备（如 YubiKey 替代品）的安全性。它强调了硬件攻击者与防御者之间持续不断的军备竞赛。 该攻击在初始发现和记录阶段需要约 25 万美元的实验室设备，但社区成员估计复现成本可低于 2.5 万美元，甚至可能低于 1 万美元。该技术涉及差分光子发射显微镜以缩小激光搜索区域，然后通过 SWD 引导注入设置恢复安全调试所需的两比特位。

hackernews · synack · Sep 18, 16:54 · [社区讨论](https://news.ycombinator.com/item?id=49757050)

**背景**: 激光故障注入是一种强大的主动攻击，利用聚焦激光在芯片电路中诱发故障，通常用于绕过安全机制。光子发射显微镜是一种非侵入式技术，通过检测晶体管开关时发射的光子来映射活跃晶体管，有助于定位特定寄存器。RP2350 是一款带有安全飞地的微控制器，旨在保护敏感数据和调试访问，因此成为安全研究的目标。
