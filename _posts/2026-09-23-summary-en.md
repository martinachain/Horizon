## [Trail of Bits Calls SAML 'A Fractal of Bad Design'](https://blog.trailofbits.com/2026/09/21/saml-a-fractal-of-bad-design/) ⭐️ 8.0/10

Trail of Bits published a critical analysis titled 'SAML: A fractal of bad design,' arguing that the Security Assertion Markup Language is fundamentally flawed and comparing it unfavorably to modern alternatives such as OpenID Connect (OIDC). The post, which scored 8.0/10 and drew 201 points and 123 comments on Hacker News, highlights security pitfalls rooted in SAML's XML-based design. SAML remains the dominant protocol for enterprise single sign-on, so its design flaws directly affect the security of countless corporate identity systems. The discussion reflects growing momentum toward OIDC as a replacement, though the community notes that migration is far from trivial for organizations selling to enterprises. The article focuses on SAML's complexity, particularly around XML signature processing, which has historically enabled vulnerability classes such as XML signature wrapping and canonicalization errors. Community members added that OIDC has its own issues, including JWT algorithm confusion, 'none' algorithm attacks, and missing audience checks, so neither protocol is a clean win.

hackernews · aray07 · Sep 22, 18:57 · [Discussion](https://news.ycombinator.com/item?id=49806335)

**Background**: SAML is an open standard for exchanging authentication and authorization data between an identity provider and a service provider, commonly used for enterprise single sign-on. It relies on XML for message formatting and XML digital signatures for security, which makes implementations complex and error-prone. OIDC is a newer authentication layer built on top of OAuth 2.0 that uses JSON Web Tokens (JWTs) instead of XML, and it has become the default for consumer-facing sign-in with Google, Microsoft, and others.

## [FoxPro revived on Rust/WASM runtime after Microsoft killed it in 2007](https://foxscript.org/) ⭐️ 7.0/10

A project called FoxScript has reimplemented the Visual FoxPro language on a new runtime written in Rust and compiled to WebAssembly, checked against the real vfp9.exe for compatibility. Many businesses still depend on Visual FoxPro applications that are too costly to rewrite, so this revival lets them keep running legacy software while gaining modern capabilities. It also demonstrates how Rust and WebAssembly can be used to modernize and preserve aging language ecosystems. The project is MIT-licensed, but reports are not yet implemented and the builds are unsigned, which may raise trust and deployment concerns. Compatibility is validated against the actual vfp9.exe, and legacy 32-bit .fll add-ins continue to load despite the new runtime.

hackernews · boredjohnny · Sep 22, 21:00 · [Discussion](https://news.ycombinator.com/item?id=49808023)

**Background**: Visual FoxPro is a data-centric, object-oriented programming language and database IDE developed by Microsoft, descended from FoxPro and FoxBASE. Its final version, 9.0, shipped in 2004 with an SP2 update in 2007, and Microsoft ended support in 2015. WebAssembly is a portable binary format that lets languages run efficiently across platforms, while Rust is a systems language focused on performance and memory safety.
