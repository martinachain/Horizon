## [Turbopuffer v3 Declares the Standalone Vector Database Dead](https://turbopuffer.com/blog/rip-vector-database) ⭐️ 8.0/10

Turbopuffer published a blog post titled 'RIP, vector database' arguing that dedicated vector databases are obsolete, and introduced turbopuffer v3, which treats approximate nearest neighbor (ANN) search as a secondary index rather than the primary storage layout. The change means vectors are no longer keyed by their ANN address, mirroring how traditional databases like Postgres and MySQL build secondary indexes. This challenges the standalone vector database paradigm that has dominated AI infrastructure, suggesting that vector search should be a feature of general-purpose databases rather than a separate product category. If the argument holds, it could reshape how AI applications store and retrieve embeddings, affecting vendors like Pinecone, Weaviate, and Qdrant. Turbopuffer is built on object storage with a write-ahead log (WAL), achieving high write throughput (~10,000+ vectors/sec) at the cost of higher write latency (p50=165 ms). The v3 architecture decouples the ANN index from row storage, so reindexing no longer requires rewriting the underlying data, trading lookup cost for reindexing cost in a way analogous to MySQL versus Postgres index design.

hackernews · razin · Oct 1, 16:01 · [Discussion](https://news.ycombinator.com/item?id=49923466)

**Background**: Vector databases store high-dimensional embeddings and use approximate nearest neighbor (ANN) search to find similar items quickly, which is essential for AI applications like semantic search and recommendation systems. Traditionally, these databases treat the ANN index as the primary storage structure, meaning every update can trigger expensive index rewrites. Turbopuffer's approach instead keeps rows in object storage fragments and treats the ANN index as a secondary structure that never moves the rows, similar to how relational databases handle secondary indexes.

## [Pi Durable: A Durable Agent Harness for Unattended AI Agents](https://earendil.com/posts/pi-durable/) ⭐️ 7.0/10

Pi Durable is a new durable agent harness from earendil-works that makes long-running, unattended AI agents survive process crashes such as kill -9. It reuses Pi's model runtime, auth, settings, system prompt, keybindings, theme, and interactive components, with the agent itself implemented as the durable Harness plus built-in CodingTools. Durable execution is becoming a key infrastructure layer for production AI agents, with major players like LangChain Deep Agents, Vercel Eve, OpenAI Agents API, and Anthropic Managed Agents all building in this space. Pi Durable brings a respected developer's take to the problem, potentially influencing how agent frameworks handle fault tolerance and resumability. The entire source code, excluding tests, is about 15,000 lines, which the author notes comes out to roughly 150,000 tokens with GPT and about 250,000 with Claude. A notable design choice is that Durable does not support branching conversation trees, only conversation forks with ancestry information, which some community members question as necessary for durability guarantees.

hackernews · paulsmith · Oct 1, 19:24 · [Discussion](https://news.ycombinator.com/item?id=49925969)

**Background**: Most agent runtimes model a run as a while loop: send context, take the response, execute tools, push onto an array, and repeat, with the array living in memory. If the process is killed between a tool executing and the push, the tool ran but nothing in the system knows it did. Durable execution frameworks like Temporal, Restate, and DBOS solve this by making long-running tasks fault-tolerant, resumable, and production-ready, and Pi Durable applies this approach specifically to AI agent harnesses.

## [DogeOS Launches Testnet to Bring EVM Smart Contracts to Dogecoin](https://www.theblock.co/news/ecosystems/2026-09-30-dogeos-launches-public-testnet-dogecoin-zk-rollup-evm-417307) ⭐️ 6.0/10

DogeOS launched a public testnet for a zero-knowledge rollup that enables EVM smart contracts on Dogecoin, with DOGE used to pay gas fees. This marks the first public testing phase of DogeOS's plan to add Ethereum-style programmability to the Dogecoin network. Dogecoin has historically been limited to simple payments, so adding EVM compatibility could let developers build DeFi apps, games, and other applications on top of it. If successful, this could expand Dogecoin's utility and attract developers from the broader Ethereum ecosystem. The rollup uses zero-knowledge proofs to move computation and state off-chain while inheriting Dogecoin's security, and gas fees are denominated in DOGE rather than a separate token. As a testnet, it is not yet production-ready and its performance, security, and adoption remain unproven.

rss · The Block · Sep 30, 18:23

**Background**: Zero-knowledge rollups are layer-2 scaling solutions that increase throughput by moving computation and state storage off-chain while posting validity proofs to the main chain. EVM smart contracts are programs written for the Ethereum Virtual Machine, the standard execution environment for most decentralized applications. DogeOS is an app layer that aims to bring Ethereum-like UX and programmability to Dogecoin, whose base layer was designed primarily for payments.
