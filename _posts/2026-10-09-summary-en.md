## [DuckDB Labs Launches DuckLake, a SQL-Catalog Data Lake Format](https://github.com/duckdb/ducklake) ⭐️ 8.0/10

DuckDB Labs has introduced DuckLake, an open data lake (lakehouse) format that stores all table metadata in an ACID SQL database while keeping actual data in Parquet files on object storage. It is designed to work with DuckDB and other query engines, and has already spawned ecosystem efforts such as a Rust/DataFusion port and the Quack protocol. DuckLake offers a simpler alternative to Apache Iceberg and Delta Lake by replacing file-based metadata manifests with a SQL catalog, which could lower operational complexity for lakehouse deployments. Its emergence signals that the DuckDB ecosystem is expanding from an embedded analytics database into a broader data platform, affecting data engineers and analytics teams evaluating open table formats. DuckLake is still alpha-quality software: community reports note that on v1.5.4 catalog-filtered counts are broken, and the SQL parser in DuckDB v2 is roughly 10x slower. Access controls are limited to what the underlying object storage bucket supports, meaning no column-level or row-level security and no column masking.

hackernews · saikatsg · Oct 7, 17:40 · [Discussion](https://news.ycombinator.com/item?id=49996149)

**Background**: DuckDB is an open-source, column-oriented embedded relational database specialized for OLAP (analytical) workloads, similar in spirit to SQLite but optimized for large-scale analytics rather than transactions. A lakehouse combines the cheap storage of a data lake with the table semantics and reliability of a data warehouse, and existing formats like Apache Iceberg and Delta Lake typically store metadata as files (manifests) in object storage. DuckLake's key design choice is to instead keep that metadata in a SQL database, which provides ACID guarantees and a familiar query interface.

## [Cactus Compute Releases Whistle, a 16.9 MB On-Device Speech-to-Text Model](https://cactuscompute.com/blog/whistle) ⭐️ 7.0/10

Cactus Compute has released Whistle, a compact speech-to-text model that weighs just 16.9 MB and runs locally on CPUs. It supports English, German, French, Spanish, Italian, Dutch and Polish, and can transcribe a 16 kHz mono recording of up to 30 seconds in a single pass while returning word-level timestamps and probabilities. Whistle shows that useful ASR can now fit into a tiny on-device footprint, which matters for privacy-first, offline and embedded applications where sending audio to the cloud is undesirable. It also lowers the barrier for hobbyists and edge developers who want speech input without a GPU or a large model download. The model is quantization-aware trained and ships as a single on-device file, and it shares the container and engine of Cactus's 14 MB Needle tool-calling model, so one build can give Needle audio input. Community testing suggests accuracy is well below larger models like Qwen ASR in free-form transcription, and it lacks streaming output during recording.

hackernews · gmays · Oct 8, 16:59 · [Discussion](https://news.ycombinator.com/item?id=50008427)

**Background**: Speech-to-text (ASR) models have traditionally been large and compute-heavy, often requiring cloud servers or powerful GPUs. Recent work on model compression, quantization and edge-first architectures has pushed ASR toward small, local models that run on CPUs or NPUs. Whistle is part of this trend, trading some accuracy for a footprint small enough to embed in almost any device.

'Harvest now, decrypt later' is a surveillance strategy where encrypted data is stored today with the expectation that future quantum computers will be able to decrypt it, prompting calls for post-quantum cryptography migration well before the threat fully materializes.
